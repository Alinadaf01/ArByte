## نتیجه‌گیری

`rtl-theme.com` یک سایت شناخته‌شده‌ی توزیع نسخه‌های **کرک‌شده/غیرمجاز** افزونه‌های وردپرس است.
این‌که خودِ فایل بررسی لایسنس هم توسط همین سایت دوباره رمزگذاری شده، یعنی نسخه‌ی اصلی
(محافظت‌شده توسط فروشنده‌ی واقعی) باز و دستکاری شده، و این کپی توسط توزیع‌کننده‌ی غیرمجاز
دوباره بسته‌بندی شده — نه یک وابستگی معمولی به سرور لایسنس فروشنده (چیزی که سند تسک §۱.۲
پیش‌بینی کرده بود)، بلکه **نسخه‌ای غیرمجاز از یک محصول تجاری**.

با ionCube رمزگذاری‌شده یعنی حتی در صورت تمایل، **از نظر فنی هم** سورس قابل‌خواندن نیست —
رمزگشایی‌اش نیازمند دور زدن DRM است (Digital Rights Management)، کاری که این دستیار انجامش
نمی‌دهد، صرف‌نظر از دستور تسک. در نتیجه هیچ جزئیات پیاده‌سازی‌ای (endpoint واقعی، احراز
هویت، امضای webhook) قابل استخراج نبود — نه فقط به‌خاطر «کپی نکردن کد» (که سند تسک هم صریح
خواسته بود)، بلکه چون **چیزی برای خواندن وجود نداشت**.

`help.pdf`/`help-video.mp4` هم بخشی از همین بسته‌ی توزیع‌شده‌ی غیرمجازند — طبق همان منطق،
برای طراحی این استفاده نشدند (منبع آلوده، نه فقط فایل رمزگذاری‌شده‌اش).

## پیامد برای پروژه

- ⚠️ **این فایل specifically نباید در هیچ سروری (dev/staging/production) نصب یا استفاده شود** —
  ریسک قانونی مستقیم برای مالک پروژه (استفاده از نرم‌افزار تجاری بدون لایسنس معتبر)،
  جدا از هر ریسک امنیتی (کد رمزگذاری‌شده از منبع نامعتبر می‌تواند هر کاری بکند، از جمله
  backdoor — هیچ راهی برای audit کردنش نیست).
- بخش ۱.۳ (provider واقعی بله‌پی) ساخته نشد. اسکلت `apps/orders/providers/balepay.py`
  از `D-05` دست‌نخورده ماند (هر دو متد `PaymentProviderError` می‌اندازند).
- **کارت‌به‌کارت دستی `D-05` روش پرداخت فعال می‌ماند** — چیزی غیرفعال نشد، چون بله‌پی
  هرگز فعال نشد (§۱.۳'s «بعد از فعال شدن بله‌پی» هرگز رخ نداد).
- `GET /payment-methods` بدون تغییر: کارت‌به‌کارت (اگر `SiteSettings` پر شده) + `GATEWAY`
  فقط اگر یک `ApiCredential` واقعاً معتبر (بله‌پی یا هر درگاه دیگر) در آینده تنظیم شود —
  چیزی که با این فایل ممکن نیست.

## برای رسیدن به بله‌پی واقعی

سه راه، هیچ‌کدام با این فایل:

1. **مستندات API رسمی بله** (در صورت وجود انتشار عمومی از بله/بانک مرکزی برای پرداخت
   کارت‌به‌کارت/کیف پول در ربات) — باید جدا پیدا و بررسی شود، نه از این بسته.
2. **خرید نسخه‌ی اصلی و مجاز** افزونه (یا دسترسی مستقیم API از فروشنده‌ی واقعی، نه
   `rtl-theme.com`) — اگر مدیر پروژه چنین دسترسی‌ای تهیه کند، آن‌وقت بخش ۱.۳ همین تسک
   قابل‌اجراست.
3. یک درگاه پرداخت **دیگر** با مستندات عمومی رسمی (زرین‌پال/آیدی‌پی، که اسکلت‌شان از قبل
   در `apps/orders/providers/` هست) — این‌ها جایگزین معماری بله‌پی نیستند اما مسیر امن‌تری
   برای «فعال‌کردن درگاه واقعی» در آینده‌اند.
