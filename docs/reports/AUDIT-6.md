# AUDIT-6 — Torob API v3

وضعیت: ✅ کد و تست کامل. فعال‌شدن به **کلید عمومی ترب** نیاز دارد (Q-48). مرجع: `docs/integrations/torob-api-v3.pdf` (خلاصه در `torob-api-v3.md`).

## وضعیت قبلی (G-02)

`GET /feeds/torob?page=N` با قالب حدسی (Q-43). فاصله‌اش با v3:

- بدون احراز.
- صفحه‌بندی روی محصول، نه آیتم.
- کش یک‌ساعته، یعنی داده‌ی کهنه.
- `availability` به‌صورت رشته.
- فیلدهای اضافه: `brand`، `condition`، `currency`، `image_link`.
- بدون `api_version`، تاریخ‌ها، cursor و جست‌وجو با آدرس/شناسه.

**تصمیم:** دست نخورد و کار می‌کند، چون مستند v3 آن را منسوخ اعلام نکرده. بعد از تأیید v3 در پنل ترب حذف شود.

## تغییرات

- **اپ `apps/torob`:**
  - `feed.py`: ساخت آیتم، اعتبارسنجی، و چهار حالت درخواست.
  - `auth.py`: احراز JWT.
  - `views.py`: endpoint.
  - `admin_views.py`: پنل.
  - مدل `TorobFetchLog`.
- **Endpoint:** `POST https://api.arbyte.ir/api/torob/v3/products`. از مسیر `/api/` فعلی nginx می‌گذرد، پس تغییر nginx لازم نیست.
- **هر واریانت قابل‌فروش یک آیتم است.** همه‌ی داده از منابع خود فروشگاه می‌آید:
  - `build_product_detail` و قانون `PUBLIC_PRODUCT_Q` (AUDIT-1)؛ پس محصول حذف‌شده، پنهان یا بی‌واریانت اصلاً نمی‌آید.
  - قیمت از `live_price` (با کمپین)؛ `old_price` همان قیمت قبل از تخفیف است.
  - موجودی از `compute_availability`.
  - `page_url` = `https://arbyte.ir/products/<slug>?v=<id>`.
  - `subtitle` = برند + مدل.
  - `spec` = کل جدول مشخصات به‌اضافه‌ی محورهای واریانت؛ مستند جدول کامل را می‌خواهد، نه فقط مشخصات کلیدی.
  - وضعیت کالا (اپن‌باکس و…) در عنوان می‌آید، چون v3 فیلدی برایش ندارد.
- **داده‌ی زنده:**
  - صفحه‌بندی و cursor در سطح query است (۱۰۰تایی) و کشی در کار نیست، چون مستند آن را مجاز نکرده.
  - `date_updated` = بیشترینِ تاریخ تغییر واریانت، محصول و انبار.
- **خطاها:**
  - ورودی نادرست → `400 {"error}` (مثلاً همان «sort parameter is not provided» مستند).
  - توکن نامعتبر یا نبودن آن → `401`.
  - آیتمی که اعتبارسنجی مستند را رد کند کنار گذاشته و لاگ می‌شود و کل پاسخ را نمی‌شکند.
- **امنیت:**
  - کلید عمومی در `ApiCredential(service="torob")` رمزشده ذخیره می‌شود و `is_active` روشن/خاموش اتصال است.
  - فقط الگوریتم نامتقارن هم‌نوع کلید پذیرفته می‌شود؛ HS*/none رد می‌شوند.
  - توکن و کلید هرگز لاگ نمی‌شوند و به مرورگر نمی‌رسند؛ پنل فقط اثرانگشت کلید را نشان می‌دهد.
  - ترب در داشبورد درگاه‌ها شمرده نمی‌شود.
- **پنل «ترب»:** فعال/غیرفعال، اثرانگشت کلید، آدرس endpoint، تعداد آیتم، آخرین دریافت موفق، درخواست/خطا/آیتم ردشده در ۲۴ ساعت، ۱۰ خطای آخر، و دکمه‌ی **Validate feed**. این دکمه چیزی به ترب نمی‌فرستد و در لاگ فعالیت ثبت می‌شود.
- **Migration:** `settings.0006` (فقط choices) و `torob.0001` (جدول لاگ). هر دو بی‌خطر روی داده‌ی تولید.

## آزمون

- Django: **۴۸۱ تست سبز** (۲۱ تست تازه‌ی ترب). ruff تمیز؛ migration معلق ندارد.
- تست‌های تازه‌ی ترب این‌ها را پوشش می‌دهند:
  - فیلدها و پاکت دقیقاً مطابق کلاس Product مستند.
  - هر چهار حالت، با صفحه‌بندی کامل و cursor تا انتها، بدون تکرار.
  - قیمت کمپین، ناموجودی، پنهان/حذف‌شده، و آیتم نامعتبر.
  - ۱۳ حالت 400.
  - احراز: بدون توکن، کلید دیگر، منقضی، HS256، none، و کلید یک‌خطی.
  - لاگ نشدن توکن، و دسترسی پنل.
- پنل ادمین: typecheck و build سبز.
- مستند sandbox ترب معرفی نکرده، پس تست یکپارچه با سرور ترب ممکن نبود.

## کار مالک (به ترتیب)

1. این شاخه را deploy کنید (`deploy.sh` خودش `migrate` را اجرا می‌کند).
2. پنل ترب → **راهنمای توکن** (`/s/torob_api_token_guide`) → کلید عمومی را کپی کنید.
3. پنل آربایت → تنظیمات → کلیدهای API → «کلید جدید» → سرویس **ترب**، کلید `publicKey` = متن کامل کلید، فعال → ذخیره.
4. پنل آربایت → **ترب**: وضعیت «فعال» و اثرانگشت دیده شود. «Validate feed» باید ۰ نامعتبر بدهد.
5. پنل ترب → ادغام / Torob API → آدرس `https://api.arbyte.ir/api/torob/v3/products` را ثبت و درخواست بررسی بدهید.
6. بعد از اولین دریافت، صفحه‌ی ترب «آخرین دریافت موفق» را نشان می‌دهد. خطاها در همان صفحه می‌آیند.
7. صفحه‌ی راهنمای توکن را هم در `docs/integrations/` بگذارید (Q-48).
