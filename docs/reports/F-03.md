## موتور قیمت (`apps/catalog/pricing.py`)

- FIXED دست نمی‌خورد. SUPPLIER_PLUS_PROFIT: قیمت همکار = ارزان‌ترین `SupplierProduct` در دسترسِ تأمین‌کننده‌ی فعال (نبودش = `supplier_price` دستی). سود: واریانت ← قانون همان تأمین‌کننده ← دسته ← دسته‌ی والد ← سراسری؛ گرد به ۱۰۰۰ بالا با **حساب صحیح**.
- **باگ پیدا و رفع شد:** با float، ‏۱۲٬۰۰۰٬۰۰۰×۱٫۱ به ۱۳٬۲۰۱٬۰۰۰ گرد می‌شد. همین خطا در قیمت انبوه F-02 هم بود (۱٬۲۰۰٬۰۰۰ +۱۰٪ → ۱٬۳۲۱٬۰۰۰)؛ هر دو با حساب صحیح/Decimal درست شدند و تست رگرسیون دارند.
- تغییر قیمت همکار (ساخت/ویرایش/حذف، فعال‌سازی تأمین‌کننده) و ذخیره‌ی جدول واریانت → بازمحاسبه‌ی واریانت‌های وابسته + `PriceHistory` با دلیل. «بازمحاسبه‌ی همه»: پیش‌نمایش، بعد اعمال همان تغییرها؛ واریانت‌های بدون قیمت همکار یا قانون جدا گزارش می‌شوند.
- امنیت: قیمت همکار/سود فقط با `cost_price`؛ تست امنیت API عمومی موجود سبز + تست تازه (هیچ supplier/profit در پاسخ محصول).

## ورود اکسل

آپلود → سرستون‌ها + نگاشت پیشنهادی (نگاشت دفعه‌ی قبل یا تطبیق نام) → پیش‌نمایش هر ردیف ایجاد/به‌روزرسانی/خطا با دلیل (**بدون نوشتن**) → اجرا در Celery → گزارش + اکسل ردیف‌های خطادار. SKU کلید تطبیق؛ ردیف‌های هم‌«کد محصول مادر» یک محصول؛ مشخصات با ستون `spec:<key>`؛ ارقام فارسی و جداکننده پذیرفته می‌شوند. قالب نمونه با برگه‌ی راهنما. نگاشت به شکل جفت `{field, header}` در API (رندرر camelCase کلید dict را عوض می‌کرد).

## کمپین

`live_price()` در بازه‌ی فعال `price.final` = قیمت کمپین و `compareAt` = قیمت قبلی را برای فهرست، جزئیات، فیلتر قیمت، سبد و سفارش (snapshot) برمی‌گرداند — قیمت ذخیره‌شده دست نمی‌خورد (Q-37). دسته شامل زیردسته‌ها. Celery beat هر ۵ دقیقه شروع/پایان‌ها را revalidate می‌کند. ادمین: CRUD با انتخاب محصول/دسته و پیش‌نمایش قیمت‌ها.
