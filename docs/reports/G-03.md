# G-03 — حذف Nest، CI، سخت‌سازی امنیتی

وضعیت: ✅ کامل (وضعیت CI در انتهای گزارش)

## حذف

- `apps/api` (NestJS + Prisma، ~۳۶۰۰ خط lockfile)، `infra/docker/api.Dockerfile`، اسکریپت‌های `db:*` و `contract:parity` (+ `parity.ts`)، کانفیگ‌های `eslint/nest.js` و `typescript/nestjs.json`، وابستگی `tsx`.
- پیش از حذف: `seed_arbyte` از fixture ثبت‌شده در git کار می‌کند (دیگر به `export-catalog` Nest نیازی نیست)؛ پیش‌فرض آدرس API در فروشگاه از پورت ۴۰۰۰ (Nest) به ۸۰۰۰ (Django).
- **مدل داده**: `docs/data-model.md` و `docs/erd.md` حالا خودکار از مدل‌های Django ساخته می‌شوند: `pnpm be:manage generate_data_model`.
- کد بی‌مصرف (knip): `ProductRailSection`، `ImageSlot`، `ImageUploader` پنل حذف شدند. بقیه‌ی گزارش‌های knip (کانفیگ eslint، فایل‌های طراحی `docs/design`) مثبت کاذب‌اند.
- `docker-compose.dev.yml` فقط Postgres (دیتابیس `arbyte_dj`) و Redis دارد. MinIO و Mailpit استفاده نمی‌شدند.
- README ریشه: راه‌اندازی dev از صفر در ۵ قدم، استک واقعی (Django/Celery/Vite)، badge CI.

## CI — `.github/workflows/ci.yml`

روی هر push و PR چهار job اجرا می‌شود:

- **secrets**: gitleaks روی کل تاریخچه.
- **backend**: `manage.py test` با سرویس Postgres و Redis، `ruff`، `makemigrations --check`، `check --deploy --fail-level WARNING`.
- **frontend**: `typecheck`، `lint`، `test`، `build` فروشگاه و پنل.
- **integration**: Django بالا با seed، `contract:test`، E2E فروشگاه (سبد → کوپن → ورود → آدرس → کارت‌به‌کارت → سفارش) و `seo:audit` روی build تولیدی.

کش pip و pnpm فعال است.

## امنیت

- **`check --deploy`**: بدون هشدار. HSTS، کوکی امن، `SECURE_*`، `X_FRAME_OPTIONS=DENY`، Referrer/COOP. `CSRF_TRUSTED_ORIGINS` و CORS فقط از env. Swagger/schema فقط در DEBUG. Django admin داخلی در تولید خاموش است، مگر با مسیر مخفی `DJANGO_ADMIN_URL`.
- **Next**: CSP با nonce بازبینی شد (`connect-src` فقط خود سایت و API، `object-src 'none'`، `img-src` + اینماد). هدرهای nosniff، Permissions-Policy و COOP اضافه و `X-Powered-By` حذف شد.
- **نرخ محدود از env** برای OTP درخواست/تأیید، ورود ادمین، فرم تماس، پیگیری سفارش، **آپلود رسید (تازه)**، API عمومی، بازدید و ریدایرکت. کلید نرخ آی‌پی واقعی کاربر است (G-02: `X-Client-IP` امضاشده از BFF، `X-Real-IP` nginx).
- **آپلود رسید** (باگ امنیتی رفع شد):
  - نوع فایل به `Content-Type` ادعایی مرورگر اعتماد می‌کرد؛ حالا **magic bytes** بررسی می‌شود (JPEG/PNG/WebP/PDF).
  - نام اصلی فایل حفظ می‌شد؛ حالا **نام تصادفی** است.
  - فایل‌ها داخل `MEDIA_ROOT` بودند، یعنی از `/media/receipts/...` و rewrite فروشگاه **عمومی** در دسترس بودند. حالا در `PRIVATE_MEDIA_ROOT` خارج از مسیر عمومی‌اند و فقط endpoint ادمین سروشان می‌کند. migration فایل‌های قبلی را جابه‌جا کرد.
  - تصاویر پنل از قبل re-encode به WebP با نام تصادفی و سقف ۸MB بودند.
- **ورود ادمین**: قفل موقت بعد از `ADMIN_LOGIN_MAX_FAILURES` (۵) شکست پشت‌سرهم، هم برای هر شماره و هم برای هر آی‌پی، به مدت `ADMIN_LOGIN_LOCK_MINUTES` (۱۵). پاسخ ۴۲۹ است، حتی با رمز درست. مدل `AdminLoginAttempt` همه‌ی ورودها را ثبت می‌کند (موفق، ناموفق، قفل؛ آی‌پی و UA) و در پنل «لاگ فعالیت» بخش «ورودهای پنل» اضافه شد.
- **audit**:
  - `pip-audit`: بدون آسیب‌پذیری.
  - `pnpm audit`: ۳ critical و ۱۱ high بود. رفع با `next` 15.5.24، `sharp` 0.35.4 (خروجی AVIF تأیید شد)، `vitest` 3.2 و override نسخه‌ی وصله‌شده‌ی `postcss`، `fast-uri`، `js-yaml` و `vite`. **۰ high/critical**. دو moderate باقی مانده در `vitest` فقط ابزار تست محلی‌اند و به build تولیدی نمی‌رسند (رفعشان vitest 4 است).
- **gitleaks** روی کل تاریخچه (۴۸ کامیت): ۲ یافته، هر دو **مقدار ساختگی داخل تست** (`SECRETKEY-ABCD1234`، `tok_live_abcdef123456`)، در `.gitleaksignore`. **هیچ secret واقعی در تاریخچه نیست.** `apps/api/.env.test` حذف‌شده هم چیزی نداشت.
