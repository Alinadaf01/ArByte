# G-02 — سئو، فید ترب، پرفورمنس

وضعیت: ✅ کامل

## سئو فنی

- **sitemap.xml** پویا (`app/sitemap.ts`): صفحه‌های ثابت + دسته‌ها + محصولات فعال + نوشته‌ها با `lastmod` از `GET /seo/sitemap`. در یک فایل تا سقف ۵۰هزار آدرس؛ اگر بزرگ‌تر شد، `generateSitemaps`.
- **robots.txt**: بسته بودن `/cart`، `/checkout`، `/account`، `/orders`، `/login`، `/wishlist`، `/compare`، `/track-order`، `/search`، `/api/` و پارامترهای فیلتر (`sort`، `brand`، `maxPrice`، `inStock`، `spec`)؛ لینک sitemap.
- **ریدایرکت**: مدل `Redirect` (migration `content.0010`) و پنل «ریدایرکت‌ها» (جستجو، خودکار/دستی، شمارش بازدید، جلوگیری از حلقه). تغییر slug محصول، دسته یا نوشته، و حذف محصول (به دسته‌اش) **خودکار ۳۰۱** می‌سازد؛ زنجیره‌ها جمع و slug دوباره‌زنده پاک می‌شود. middleware فروشگاه جدول را ۶۰ ثانیه کش می‌کند و query را حفظ می‌کند.
- **ممیزی**: title و description یکتا با fallback برای محصول و دسته، canonical مطلق، `noindex` صفحه‌های خصوصی و فیلترشده، OG و Twitter در هر صفحه. JSON-LD: `Organization` (همه‌جا)، `WebSite`+`SearchAction` (خانه)، `Product`+`BreadcrumbList`، `Article`+`BreadcrumbList`. **اسکریپت** `pnpm --filter @arbyte/web seo:audit [URL]` همه‌ی موارد بالا را روی مسیرها و نمونه‌ی sitemap بررسی می‌کند: سبز.
- باگ Next 15: متادیتا برای کاربرِ «غیربات» در `<body>` استریم می‌شد و Lighthouse و ترب description را نمی‌دیدند. `htmlLimitedBots` رفع شد.

## فید ترب

`arbyte.ir/feeds/torob` (rewrite به Django). هر واریانت یک آیتم (`page_unique`=SKU)، قیمت نهایی با کمپین، موجودی واقعی، تصویر، وضعیت کالا در عنوان؛ کش ۱ ساعت (Q-43).

## پرفورمنس — Lighthouse موبایل (build تولیدی، محلی)

| صفحه              | قبل (Perf/A11y/BP/SEO) | بعد                      |
| ----------------- | ---------------------- | ------------------------ |
| `/`               | 84 / 96 / 96 / 92      | **90 / 100 / 100 / 100** |
| `/products`       | 91 / 98 / 96 / 100     | **86 / 100 / 100 / 100** |
| `/products/<msi>` | 88 / 100 / 96 / 100    | **87 / 100 / 100 / 100** |
| `/blog/<post>`    | 94 / 100 / 96 / 100    | **94 / 100 / 100 / 100** |

(نوسان Perf بین اجراها ±۵ است. LCP هر چهار صفحه متن است و تأخیرش اجرای JS زیر CPU چهاربرابر کند است، نه دانلود.)

- فونت: `next/font` نسخه‌ی hashed می‌ساخت و preload دستی ۴۰۰/۷۰۰ فایل دیگری بود: **هر بازدید فونت را دو بار دانلود می‌کرد**. حالا `@font-face` روی فایل‌های `/public` و preload همان فایل‌ها.
- لوگو: `sizes` نداشت و نسخه‌ی ۳۸۴۰px را می‌گرفت (۲۰KB بیهوده در هر صفحه).
- تصاویر AVIF/WebP و lazy (پیکربندی موجود)؛ کنتراست دو متن و ترتیب سرتیترها رفع شد.
- **کش HTTP**: `Cache-Control: public, max-age=60, stale-while-revalidate=300` و `ETag` برای GETهای عمومی مهمان (ETag بدون `requestId` تصادفی، پس 304 واقعی). درخواست دارای Authorization `private, no-store` می‌گیرد. ISR صفحه‌ها با revalidate پنل (F-02) سر جایش است.
- **بازدید**: `POST /analytics/pageview` بدون کوکی (hash روزانه‌ی آی‌پی و UA، بات‌ها رد) → `PageView`/`DailyStat` داشبورد وایب.

## باگ‌های پیداشده

- پراکسی BFF هر پاسخ 204 را 500 می‌کرد.
- BFF آی‌پی کاربر را نمی‌فرستاد: همه‌ی نرخ‌های per-IP (OTP، تماس، ورود ادمین) بین همه‌ی کاربران مشترک بود. حالا `X-Client-IP` امضاشده با `BFF_SHARED_SECRET`، و `X-Real-IP` nginx با `TRUST_X_REAL_IP`.
- `REVALIDATE_SECRET` در `.env.example` نبود (F-02)؛ اضافه شد.
