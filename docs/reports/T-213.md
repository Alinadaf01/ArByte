# T-213 — فروشگاه و فیلترها

وضعیت: ⚠️ کامل با پیش‌فرض

## انجام شد

- `/products` (بدون فیلتر دسته) و `/category/[slug]` (پیش‌فیلترشده) یک مجموعه کامپوننت مشترک (`components/shop/`) دارند: `ShopControls` (ارکستر کلاینت — `useTransition` مشترک برای همه‌ی فیلترهای پارامتری)، `ShopFilterPanel` (محتوای فیلتر، هم دسکتاپ هم داخل Sheet موبایل)، `ShopProductGrid` (سرور، گرید+صفحه‌بندی). دو فایل route جدا (طبق ساختار Next.js) ولی منطق فیلتر یک‌بار نوشته شده.
- پنل فیلتر بالای گرید (دسکتاپ سه‌ستونه؛ موبایل دکمه‌ی ۵۲px + خلاصه‌ی فیلتر فعال → Sheet پایین‌صفحه)، همه از `GET /catalog/filters?category=` — دسته (چیپ، لینک واقعی)، برند (چندانتخابی، با شمارش)، حداکثر قیمت (اسلایدر داده‌محور، دیباونس ۳۰۰ms + کامیت روی `pointerup`)، فقط موجود (چک‌باکس)، مشخصه‌ی محور (فقط وقتی یک دسته انتخاب شده). گزینه‌های صفر-نتیجه غیرفعال با شمارش «۰» نشان داده می‌شوند، نه مخفی. فیلتر «شرایط کالا» طبق §۰ کلاً از UI حذف شد.
- URL تنها منبع حقیقت: `shop-params.ts` (خالص، ۱۹ تست) — `parseShopParams`/`withFilterUpdate` (هر تغییر فیلتر `page` را پاک می‌کند، `sort=featured` پیش‌فرض هرگز در URL نوشته نمی‌شود)/`buildCategorySwitchHref` (چیپ دسته سایر فیلترها را حفظ می‌کند، فقط `page`/`spec[...]` را پاک می‌کند). تغییر فیلتر یعنی `router.push` واقعی — بدون fetch کلاینتی، بدون state محلی.
- موبایل: همان `ShopFilterPanel` داخل `Sheet` موجود در `packages/ui` رندر می‌شود (کامپوننت دوم ساخته نشد). `Sheet` از قبل روی `Dialog.Root` رادیکس ساخته شده بود — تله‌ی فوکوس/Escape/قفل اسکرول رایگان آمد؛ هر سه زنده تأیید شدند (`document.activeElement` داخل دیالوگ بعد از باز شدن، `Escape` می‌بندد، `body.overflow` بین `hidden`/`visible` عوض می‌شود).
- مرتب‌سازی: `featured` (پیش‌فرض جدید، «پیشنهاد آربایت») اضافه شد — همان منطق اولویت/تاریخ `popular` را روی سرور اجرا می‌کند؛ `popular` فقط API می‌ماند، از UI مخفی است.
- `ProductCard` هم‌تراز `Products.dc.html` بازسازی شد: تصویر ۱۶/۱۱، ردیف دسته+برند به‌جای بج شرایط، لینک همیشه `?v=<defaultVariant.id>` دارد (وقتی فیلتر مشخصه‌ی محور فعال است، `defaultVariant` واریانت _منطبق_ است — منطقش از قبل در `selectCardVariant()` ساخته شده بود، فقط سیم‌کشی لازم بود). ناموجود بدون دکمه‌ی جایگزین (Q-9). یک e2e واقعی (`e2e/shop-variant-filter.spec.ts`) این قاعده را سرتاسر تأیید می‌کند: فیلتر رم روی ۳۲GB، قیمت کارت MSI Titan از ۲۸۹٬۵۰۰٬۰۰۰ به ۲۶۱٬۰۰۰٬۰۰۰ عوض می‌شود و لینک `?v=` واریانت درست را می‌گیرد.
- `/categories` بازسازی شد: یک کارت بزرگ (دسته‌ی با بیشترین `productCount`، برچسب «بیشترین موجودی» به‌جای ادعای فروش) + گرید بقیه (هرکدام با «از X میلیون» از `minPrice` جدید در `CategoryCardSchema`) + سوییچر «نمی‌دانید کدام دسته؟» (۵ گزینه‌ی کاربری، متن توصیفی عیناً از طراحی، بدون عدد ساختگی — Q-10/Q-11). جمله‌ی مقدمه حالا تعداد واقعی دسته‌ها را دارد («۵ دسته...»)، نه عدد ثابت طراحی.
- سئو: `computeShopRobotsAndCanonical` (خالص، ۴ تست) — بدون فیلتر → index + canonical خودش؛ هر فیلتر/sort → noindex,follow؛ `page≥2` بدون فیلتر → همچنان index با canonical به صفحه‌ی بدون پارامتر. با curl زنده تأیید شد (چهار حالت). صفحه‌بندی `<a href rel="prev"/"next">` واقعی (از T-202، دوباره تأیید شد).
- باگ واقعی پیدا و رفع شد: `buildCategoryHref` (یک closure سرور) مستقیم به `ShopControls` (کلاینت) پاس داده می‌شد — Next.js با خطای «Functions cannot be passed directly to Client Components» صفحه را می‌شکست. رفع: منطق نگاشت دسته→href به داخل خودِ `ShopControls` منتقل شد (از `useSearchParams()` خودش می‌سازد)، پراپ حذف شد.
- یک پراپ مرده هم در همین رفع پیدا شد: `productsBasePath` در `ShopControlsProps` تعریف شده بود ولی هرگز در بدنه‌ی کامپوننت مصرف نمی‌شد — حذف شد.

## انحراف عمدی از طراحی

- Q-10: کارت بزرگ `/categories` برچسب «پرفروش‌ترین دسته» + بازه‌ی قیمت طراحی را ندارد چون داده‌ی فروش/سقف قیمت نداریم — به‌جایش آمار واقعی (`productCount` بیشینه) + «از X میلیون».
- Q-11: سوییچر کاربری بدون عدد دستگاه ساختگی هر گزینه؛ CTA خنثی به `/products` (بدون فیلتر واقعی چون مپ کاربری→فیلتر مستند نیست).

## اعداد

- تست‌ها: **۲۷۸ سبز** در کل مونوریپو (contracts ۷۲, ui ۵۲, api ۸۹, admin ۲, web ۶۳ — ۲۰ تای جدید این تسک: shop-params ۱۹ + shop-seo ۴؛ منهای فایل‌های حذف‌شده‌ی T-202 که دیگر وجود ندارند).

- `pnpm typecheck`/`lint`/`test` سبز در هر ۷ پکیج، مونوریپو-وایید.
- بررسی زنده: `/products`، `/category/laptop-new`، `/categories` در ۳۷۵px و ۱۴۴۰px — بدون اسکرول افقی، کنسول تمیز. فیلتر مشخصه (۳۲GB) زنده تست شد (URL، قیمت کارت، لینک `?v=` — سه‌تایی درست). Sheet موبایل باز/بسته با فوکوس‌تریپ/قفل اسکرول/Escape زنده تأیید شد.
- یادداشت محیطی (نه باگ کد): `GET /api/v1/health` روی این dev-server یک خطای DI (`this.storage` undefined) می‌دهد — احتمالاً stale شدن گراف DI بعد از ساعت‌ها hot-reload، نه چیزی در این تسک تغییر کرده. اندپوینت‌های واقعی کاتالوگ (`/catalog/products`, `/catalog/filters`, `/catalog/categories/*`) که این تسک روی‌شان تکیه دارد، همه سالم پاسخ دادند؛ فقط health-check خودش تحت تأثیر است. با ری‌استارت دیو-سرور رفع می‌شود.
