## عمداً کنار گذاشته شد

- **NestJS/Prisma** (`apps/api`): جایگزین کامل با Django؛ حذف در G-03.
- **درگاه بله‌پی**: فایل رسیده کرک‌شده بود؛ فقط اسکلت خطادهنده هست تا مستند رسمی برسد (Q-29).
- **هیروی اسکرولی با فریم**: فریم‌های منبع تصاویر اپل بی‌مجوزند (Q-7).
- **UI درخواست مرجوعی در فروشگاه**: طراحی نداشت؛ API و پنل آماده‌اند (Q-33).
- **اطلاع از موجودی، یادداشت سفارش، فاکتور حقوقی، تاگل خبرنامه**: مدل/طراحی نداشتند (Q-9، Q-28، Q-22، Q-32).
- **فروشگاه روی سرور ایران**: طبق معماری روی Vercel؛ بسته به اندازه‌گیری تأخیر بازبینی شود (Q-46).

## تصمیم‌های باز برای PM (`docs/QUESTIONS.md`)

مهم‌ترها: Q-29 بله‌پی، Q-7 هیرو، Q-33 UI مرجوعی، Q-22 فاکتور حقوقی، Q-43 قالب فید ترب، Q-45 رجیستری ایمیج، Q-46 تأخیر Vercel. بقیه پیش‌فرض امن گرفته‌اند و قابل تغییرند.

## ورودی‌های لازم از کارفرما

- متن «درباره ما»، اسناد قوانین (شرایط، حریم خصوصی، ارسال، مرجوعی) و شرایط گارانتی — پنل → صفحه‌های محتوا.
- اطلاعات حقوقی فروشگاه (شناسه‌ی ملی، کد اقتصادی، نشانی، تلفن) و کد اینماد — پنل → تنظیمات.
- حساب کارت‌به‌کارت، کلید کاوه‌نگار، ۴ الگوی تأییدشده (`arbyteotp`، `arbyteorder`، `arbyteadmin`، `arbyteship`)، شماره‌های اعلان.
- کلید درگاه‌ها (زرین‌پال و …)، مستند رسمی بله‌پی.
- محصولات واقعی (به جای DEMO)، تصاویر، نوشته‌های وبلاگ.
- سرور ایران، دامنه/DNS، حساب Vercel، secretهای GitHub (در صورت Docker Hub).

## نگه‌داری کوتاه

- **استقرار**: push به `main` → ایمیج در Actions → روی سرور `./deploy/deploy.sh <sha>` (rollback خودکار). فروشگاه با push روی Vercel.
- **بک‌آپ**: cron روزانه ۰۳:۳۰؛ هر ماه یک restore آزمایشی (`deploy/restore.sh`).
- **پایش**: `scripts/smoke.sh` بعد از هر استقرار؛ پنل → داشبورد و لاگ فعالیت؛ Search Console.
- **وابستگی‌ها**: ماهانه `pnpm audit` و `pip-audit`؛ CI باید سبز بماند.
- **مدل داده**: بعد از هر migration `pnpm be:manage generate_data_model`.
- **گواهی SSL**: تمدید خودکار با cron؛ هشدار انقضا به `CERTBOT_EMAIL`.
